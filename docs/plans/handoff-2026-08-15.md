## 1. The one thing that blocks 0.24.0

**`prova run release` is red on the coverage floor, and releases now gate on it.**

`Prepare Release`'s bump-and-tag job `needs:` a gate job running the release profile, so the tag
cannot be created while the floor is unmet. That was deliberate — prova ships under the bar it asks
of everyone else — and it means the eleven unreleased commits stay unreleased until this is
settled.

| | |
|---|---|
| `rust.coverage.unit` | **72.696%** against a floor of **73.460%** |
| gap | ~217 covered lines |
| merged (`rust.coverage.lines`) | 79.05% against 84.69% |

**Why it dropped, so nobody re-diagnoses it.** The floor was banked 2026-08-11 as the closing act
of the north-star coverage arc — the high-water mark of a push whose whole purpose was raising it.
The days after landed conduct leases, selection pushdown, `--covering`, timing, lock-wait
narration, conduct identity, start budgets and this session's work: all shipping Rust proven by
black-box proofs, so the denominator outgrew the numerator. The ratchet is reporting that feature
velocity outran unit-test writing. It is not broken and the number is not noise.

**Two honest paths, and it is a judgement call:**

1. **Continue the paydown** (~217 lines). This session moved +0.40pp with 46 tests, so the
   remaining gap is roughly one more session of the same. See §2 for the worklist and the
   selection principle — done this way it keeps finding real defects, which is the argument for it.
2. **Move the floor deliberately**, with the reasoning in the commit. Defensible: it was set at a
   peak, and a ratchet whose floor was chosen at an unrepeatable moment will keep failing. If you
   do this, say so in the commit rather than in the diff alone.

**Do NOT** cover lines cheaply to clear the gate. A green gate that means nothing is worse than a
red one that means something, and the first exercise of a new release bar should not be an exercise
in getting around it.

One adjacent decision, worth settling either way: `xtask` sits in the coverage denominator at 88
lines and 0% — build automation, not shipped code. Excluding it is worth +0.23pp and is defensible
on its own merits, but decide it as scope, not as a route to green.

## 2. Continuing the paydown — the worklist and how to pick

**Selection principle, which is what made this productive:** pick by *what a silent bug costs*, not
by uncovered-line count, and prefer code that is pure enough to test precisely. The files with the
most uncovered lines (`grpc_mock`, `mcp/blocking`, `terminal`, `broker`) are mostly Lua-facing
closures needing a full harness — poor value per unit of risk. The wins came from pure logic at
data boundaries.

**Suggested next batch:** `matchers.rs`'s remaining pure core, `modules.rs`'s `emit_path` (path

filter. Roughly the size of the remaining gap, and all three are places a silent bug is expensive.

**The stopping rule:** when the remaining candidates are low-consequence files, stop. Past that
point it is number-chasing, not discovery, and the whole argument for doing it this way is gone.

## 5. Traps that cost time here — read before repeating them

- **`prova run all` is the gate; a subset you assemble is not.** Bare `prova` plus `run quality`
  misses `ut`, which is where the Rust unit tests and `learn.rs`'s 90-line-per-topic budget live.
  The switched-off line at the end of every run is the checklist, and it already says so.
- **Check a push's OUTCOME, not its plan.** `jj git push` prints `Changes to push … [move forward
  from X to Y]` BEFORE the remote answers. Filtering to that line hides a rejection completely —
  five consecutive pushes were reported as landed and none had, because the release workflow had
  moved `main` underneath them. Verify with `gh api repos/prova-rs/prova/commits/main`.
- **Never edit source while a sweep or coverage run is in flight.** The nextest deputy compiles a
  half-written tree and reports `zero cases parsed from junit.xml`, three layers from the cause.
- **Reach cargo THROUGH prova.** `prova run ut` / `prova run coverage`, or `prova lock cargo --
  cargo …` for anything ad-hoc. Bare `cargo nextest`/`llvm-cov` skips the package hold.
- **A proof of RUNTIME behavior must reach the feature through `prova.bin`.** Calling it directly
  in the proof body tests the CONDUCTING binary. The cheap check: conduct with the installed prova
  — a subject-driven proof still passes, a conductor-driven one flips.
- **`zsh` has no `PIPESTATUS`.** Capture to a file and check `$?`.
- **A failure message with captured tool output leads with whatever the tool printed first.** A
  clippy failure showed `Blocking waiting for file lock on package cache` at the top; the real
  error (dead code) was further down. Read to the end.
